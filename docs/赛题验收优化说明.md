# 赛题验收优化说明

日期：2026-11-12。基于现有 FastAPI 项目继续修改，保留现有数据结构和演示数据库。

| 评分维度 | 原有缺口 | 本轮结果 | 验证位置 |

| 流程闭环 | 超时按照预约临近时间判定 | 从工单创建起满 30 分钟未接单才顺延；不重复分配已尝试护理员；无人可派时通知人工协调 | 同上，`test_dispatch.py` |
| 流程闭环 | 取消预约后关联工单继续占用时段 | 取消、爽约同步关闭关联工单，保留审计；开放爽约接口与页面入口 | 同上 |
| 数据模型与状态机 | 回退预约异常时绕过状态机 | 只能 dispatched → pending_dispatch；已取消单不可重新打开 | 同上 |
| 算法 | 明天预约用今天负荷，评分依赖可能过期的缓存 | 按服务日期统计当日负荷，实时汇总近 30 天评价；无评价按默认评分 | 同上 |
| 算法 | 手工派单可绕过技能和半径限制 | 派单与改派统一检查技能、半径、在途冲突、日单量和项目上架状态 | 同上 |

| 数据安全 | 社区合并账单泄露其他老人明细与汇总 | 列表、详情、导出、页面按可见老人计算；个人和网格视角不展示社区统一缴费凭证 | 同上 |
| 数据安全 | 机构管理员可分配更大的范围 | 拦截街道角色及超出本人范围的授权 | 同上 |
| 结算正确性 | 负数退费明细可能再次作为退费来源 | 只选正数原明细；累计扣除已退总额与三方余额；末次精确退尽分币余额 | `test_billing.py` |
| 结算正确性 | 已派单取消计费使用调价后的金额 | 使用工单价格快照；未派单使用当前目录价格 | `test_competition_regressions.py` |
| 数据安全 | 表格文本可被识别为公式 | CSV/XLSX 转义公式前缀文本；数值金额保持数值 | `test_competition_safety.py` |
| 执行留痕 | 照片预览地址与存储目录不匹配 | 根据照片记录定位文件，校验所属工单可见性，禁止公共缓存 | `test_competition_regressions.py` |
| 隐私 | 上传原图缺少大小、像素限制 | 原图默认 10MB、2000 万像素，压缩前检查；处理方向并移除 EXIF/GPS 等元数据 | `test_competition_safety.py` |

## 复现命令

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1
```

输出：`reports/junit.xml`、`reports/coverage.xml`、`reports/htmlcov/index.html`、`reports/demo-smoke.json`。真实启动验收使用临时库，先后生成两次种子并比较各表记录数，再验证六类账号的 13 次页面访问；结束后关闭验收服务并清理临时库。

模拟可穿戴数据：

```powershell
.\.venv\Scripts\python.exe -m scripts.simulate_wearable --elder-id 1 --scenario abnormal --dry-run
.\.venv\Scripts\python.exe -m scripts.simulate_wearable --elder-id 1 --scenario abnormal --username super
```

第二条命令需要先启动服务，交互输入密码后通过正式接口上报三次心率、收缩压、血氧和步数；异常场景会触发黄、红预警。密码不会写入命令行。

## 契约说明

- `POST /api/v1/appointments` 的 `cycle_rule="weekly"` 固定创建四周，并增加返回 `occurrence_count`、`occurrences`；不选择周期时原响应保持兼容。四周之外需再次预约。
- 新增 `POST /api/v1/appointments/{id}/no-show`，请求 `{reason}`，权限 `appointment:accept`。
- `POST /api/v1/dispatch/scan-timeout` 只扫描操作者可见工单；调度任务可扫描全部工单。返回增加 `reassigned_orders`，保留原 `requeued` 和 `requeued_orders` 字段。
- 已部分退费的账单禁止再次整单红冲，应按工单退还剩余金额；负数红冲单不能再次红冲。
- 本人/网格账单视角返回 `view_scope="visible_elders"`，金额为可见明细汇总，非整个社区金额。
- 本轮不新增数据库列。价格循环外键显式声明 `use_alter`，解决测试清理警告；不会自动修改已有库的数据。

## 验证边界和提交前事项

本轮自动化验收以 SQLite 为准。Docker Compose 配置校验通过，但本机 Docker 引擎未运行，因此未完成容器构建、PostgreSQL 部署及其备份恢复验收。现有自动备份实现使用 SQLite online backup。

预警短信采用现有通知记录模拟，未连接真实短信运营商。服务范围仍依赖老人档案坐标与所属组织，未接入地址地理编码。人工受理提示不等于已实现独立人工受理队列。现有账单复核未完成真实抽样单据选择与不低于 10% 的抽查闭环。高并发抢单/退费、多实例调度互斥也未在本轮验收，不能据此声称生产就绪。

演示时应按这些边界说明实际能力。演示视频、报名编号及姓名命名、正式平台上传与回执仍需在最终提交阶段完成。原仓库存在已经跟踪的依赖缓存与运行产物，提交包应采用源码目录白名单，排除缓存、数据库、附件、密钥及虚拟环境。

源码打包命令：`python -m scripts.package_source --output dist/competition-source.zip`。脚本仅包含 app、scripts、tests、docs、docker 和项目配置，保留空的运行目录；不会将历史依赖缓存带入压缩包。这是源码审阅包，仍需加入正式演示视频后按报名信息命名提交。
