## 操作步骤

进入解压或克隆得到的项目根目录，在PowerShell中执行：

```powershell
python --version
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r requirements.txt
& '.\.venv\Scripts\python.exe' -m pip check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_dev.ps1
```

脚本在缺少`.env`时从`.env.example`复制配置，按配置定位SQLite，缺库时写入合成演示数据。已有配置与数据库不覆盖，不使用`--reset`。若`.venv`尚未创建，也可直接执行启动脚本，由其创建环境并安装依赖；Python须先可用。

## 故障处理

- Python版本/路径：`python --version`须正常返回3.10+；已验证3.12.14。若PATH中的Python损坏，使用有效解释器绝对路径创建环境，或启动时传`-BasePython 'C:\实际路径\python.exe'`。本机曾发现PATH指向不可用的旧Python310，实际运行采用独立的Python3.12.14基础解释器。
- 依赖中断：重新执行`pip install -r requirements.txt`及`pip check`。脚本对已有但不完整的`.venv`会明确报错，不能仅凭目录存在判断可运行。
- 网络错误：检查学校允许的包源和网络/代理后重试。实际计时使用本机默认清华PyPI镜像；首次下载仍需网络。
- 端口占用：用`-Port 8001`并访问对应地址；脚本不会结束占用端口的其他服务。
- 录制时禁用自动重载：添加`-NoReload`。
- 配置错误：修正`.env`和同名环境变量后重启。操作系统环境变量优先于模板；启动会在配置解析或原生命令失败时停止。
- PostgreSQL需要自行准备并初始化，本次快速验收仅覆盖SQLite。
