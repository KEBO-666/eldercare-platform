# 本轮浏览器验证与修复证据

记录性质：2026年11月12日本轮真实subagent工作摘要与证据索引。此文不是用户与AI的完整原始聊天记录，不替代比赛要求的完整Prompt链。

## 真实任务来源

用户要求：“基于此计划 确定环境没有问题之后不计成本分多个subagents并发为我完成任务”。主代理分派浏览器子任务，要求检查桌面与390px布局、三字号、键盘焦点、重复提交、派单解释，并跑通预约至预警处置主线，修复真实问题、保存截图和录像。

## 实际发现与判断

1. 读取公共脚本和预约模板时发现：局部`toast`未导出，页面却调用`App.toast`。这是静态代码线索，随后使用Edge实际探测确认，而非仅据猜测修改。
2. 隔离浏览器基线结果`reports/chuanzhi-browser/20261112-170748/result.json`记录`toast_type: undefined`；同一次记录三字号正文大小与宽度。
3. 对照Bootstrap样式与页面DOM，确认自建toast需要显式显示。修复后自动化检查不仅数DOM，还用`is_visible()`判断提示可见。
4. 在通用动作中补充防重入与等待态，并通过替换API方法为可控未完成Promise验证两次动作只发送一次请求；这项检查明确为测试注入。
5. 将预警处置提交改为等待结果，失败保留弹窗；使用明确的500注入验证输入和重试状态，真实成功分支仍调用隔离服务。
6. 候选因子解释由固定标签改为响应中的权重/贡献，并检查非默认权重场景。

## 实际工具迭代

- 首次工具使用复数表名`elders`，SQLite报无该表；核对模型后改成真实单数表名`elder/staff/user/work_order`。
- 首次启动Edge时系统TEMP权限错误；仅把工具临时路径改为本轮reports目录。
- Playwright的ffmpeg下载等待，后复用根代理独立制作环境中的ffmpeg以完成录像。
- Playwright `slow_mo=450`使派单响应的读取晚于页面400ms刷新，出现“Response body unavailable”；派单业务已完成。改为无协议慢速、关键步骤显式阅读停顿，后续通过。

以上失败保留在对应运行目录，均未冒充业务Bug或用户反馈。
